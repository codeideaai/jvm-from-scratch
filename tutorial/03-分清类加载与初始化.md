# 03 分清类加载与初始化

[English](../en/tutorial/03-class-initialization.md) · [中文](03-分清类加载与初始化.md)

配置类有静态代码块，但读取某个常量时它没有执行。这通常不是日志丢失，而是初始化根本没有被触发。本篇把“知道这个类存在”和“执行它的静态初始化逻辑”拆开观察。

## 先建立机制模型

加载负责建立类的运行时表示。链接包括验证、准备和解析；准备阶段为静态字段建立存储并设置初始值，编译期常量有特殊处理。初始化负责执行类初始化方法中的逻辑。解析允许按实现策略延迟，不能把这几个词理解为每个类都严格连续执行的一段流水线。

读取编译期常量可能已被 javac 替换成字面量，调用处无需因此初始化声明类。创建对象、调用类声明的静态方法、访问类声明的非常量静态字段则是常见触发点。

类初始化由 JVM 协调并发，成功初始化只执行一次。初始化失败也会留下错误状态；修复外部条件后，再次访问并不会自动重跑整个静态代码块。

## 完整代码

将以下内容保存为 `Demo03.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
public class Demo03 {
    static class Config {
        static final int PORT = 8080;
        static int timeout = initialize();
        static int initialize() {
            System.out.println("Config initialized");
            return 30;
        }
    }
    public static void main(String[] args) throws Exception {
        System.out.println("constant=" + Config.PORT);
        Class.forName("Demo03$Config", false, Demo03.class.getClassLoader());
        System.out.println("loaded without initialization");
        System.out.println("timeout=" + Config.timeout);
        System.out.println("timeout again=" + Config.timeout);
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo03.java
java Demo03
```

预期输出（普通验证模式）：

```text
constant=8080
loaded without initialization
Config initialized
timeout=30
timeout again=30
```

## 解释结果与证据边界

第一次输出中的 8080 可以直接进入调用方常量池。`Class.forName` 的第二个参数 false 明确要求此调用不触发初始化。直到读取 timeout，initialize 才输出标记；第二次读取只取得现有值。

调用 `Class.forName(String)` 时默认会要求初始化，这与本例的三参数版本不同。排查框架扫描阶段的副作用时，应先确认实际使用哪个重载。

若 Parent 声明静态字段而 Child 只是继承，使用 Child.field 并不意味着 Child 一定初始化。判断规则应围绕字段的声明者，而不是源码中写在点号前的类名。规则参见 [JVMS 第 5 章](https://docs.oracle.com/javase/specs/jvms/se17/html/jvms-5.html)。

补充观察命令，在本篇 class 文件所在目录执行：

```bash
javap -c -p Demo03
javap -c -p 'Demo03$Config'
```

## 把三个阶段放回这段程序

这里的 static 表示类相关字段，不要求先 new 一个 Config。final 表示赋值受限制，但“static final”不自动等于“编译期常量”：必须看类型和初始化表达式是否满足常量变量条件。本例 PORT 是基本类型，表达式也是常量；timeout 由方法执行得到。

| 观察时刻 | 能说什么 | 暂时不能说什么 |
| --- | --- | --- |
| 编译 Demo03 后 | 调用方可携带 PORT 的常量值 | Config 的静态代码已运行 |
| 三参数 forName 的 false 调用之后 | 类已被请求加载，但此调用不要求初始化 | timeout 的业务初值已计算完成 |
| 第一次读取 timeout | 触发所需初始化，执行 initialize，得到 30 | 之前的准备阶段也执行了同一业务方法 |
| 再次读取 timeout | 使用已经初始化的状态 | 每次访问都会重跑 initialize |

准备中的默认零值与源码赋值为 30 是两种不同动作。初始化过程中才会发生我们写的 println。普通外部代码按此触发规则访问时，不能简单地把“准备阶段的 0”当成一定可以读到的结果。

**新手常见问题：**Class.forName 找不到类时可能是查找失败；找到了但静态初始化抛错，则是另外一条失败路径。不要只看到“类加载出问题”就一直修改 classpath。先检查异常的类型与 cause，再判断字节从未找到，还是初始化逻辑失败。

## 动手修改与自测

将 PORT 改为 `Integer` 或改为方法调用的返回值，再看输出次序。给 initialize 增加一个必定失败的方法调用，观察首次与后续访问的异常差别。不要在长期运行应用的真实配置类上做这个破坏性实验。
