# 05 区分重载与动态分派

[English](../en/tutorial/05-method-dispatch.md) · [中文](05-区分重载与动态分派.md)

支付服务用父类型保存子类对象时，调用哪个方法？答案需要分两步：先确定方法签名，再确定这个签名对应的实现。把重载与重写混在一起，会误判框架回调和面向接口编程的行为。

## 先建立机制模型

重载选择主要发生在编译期，依据声明类型及可适用方法规则。重写的实例方法可以根据接收者的实际类型动态分派。参数对象的运行时类型不会让已经选好的重载签名自动切换。

字节码中，静态调用常见 invokestatic，接口调用常见 invokeinterface，普通虚调用常见 invokevirtual，构造器和特定特殊调用使用 invokespecial。invokedynamic 则把调用点链接交给引导机制。不要只凭源码中的关键字猜测，使用 javap 查看具体调用点。

动态分派是语义要求，不意味着每次执行都必须遍历整个继承树。JIT 可以基于类型信息优化调用，但必须保持可观察行为。

## 完整代码

将以下内容保存为 `Demo05.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
public class Demo05 {
    static class Parent {
        String name() { return "parent"; }
    }
    static class Child extends Parent {
        @Override String name() { return "child"; }
    }
    static String select(Parent value) { return "Parent overload"; }
    static String select(Child value) { return "Child overload"; }
    public static void main(String[] args) {
        Parent value = new Child();
        System.out.println(select(value));
        System.out.println(value.name());
        System.out.println(select((Child) value));
        if (!value.name().equals("child")) throw new AssertionError();
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo05.java
java Demo05
```

预期输出（普通验证模式）：

```text
Parent overload
child
Child overload
```

## 解释结果与证据边界

第一行选 Parent 参数版本，因为 value 的声明类型为 Parent。第二行调用 name 的实际实现来自 Child。第三行显式转换改变了表达式的静态类型，因此编译器选中另一个重载。

在 `javap -c -p Demo05` 中观察 select 调用后的描述符：它直接包含 Parent 或 Child 参数类型。调用点没有保留“运行时再选全部重载”的指令。

字段不遵循实例方法的重写分派。把 name 方法替换成同名字段，是另一个实验，其访问目标与声明类型有关。静态方法同样不具有本例的实例动态分派语义。

补充观察命令，在本篇 class 文件所在目录执行：

```bash
javap -c -p Demo05
```

## 动手修改与自测

增加接收 Object 的 select 重载，再把变量声明为 Object，预测输出。然后增加接口，让 Child 实现它，并通过接口引用调用，找到 invokeinterface。解释 JIT 内联后是否仍必须保持这些选择结果。
