# 15 建立可信的性能实验

[English](../en/tutorial/15-performance-experiments.md) · [中文](15-建立可信的性能实验.md)

“这个实现快了三倍”只有在实验条件和指标明确时才有意义。短程序的一次 nanoTime 差值可能主要包含类初始化、编译、计时开销或调度抖动。先保证两种实现结果一致，再决定如何测量。

## 先建立机制模型

一个可解释的基准需要固定输入分布、明确每次操作的工作量，并消费结果以防死代码消除。还需要预热以观察稳定阶段，使用独立 fork 减少同一 JVM 内不同测试互相污染。预热不能保证所有动态行为都已结束，仍须检查数据稳定性。

JMH 提供这些基础设施，但不会自动修复错误问题定义。若在基准方法内一次执行十万次业务操作，报告的每次 invocation 就包含这十万次工作；若输入完全是编译期常量，编译器可能消掉真正想测的部分。

本篇先做功能对照，完整 JMH 工程放在 examples/jmh。功能检查不打印耗时，也不宣布性能赢家，避免把一次成功运行伪装成性能结论。

## 完整代码

将以下内容保存为 `Demo15.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
import java.util.Arrays;
public class Demo15 {
    static long loop(int[] values) {
        long sum = 0;
        for (int value : values) sum += value;
        return sum;
    }
    static long stream(int[] values) {
        return Arrays.stream(values).asLongStream().sum();
    }
    public static void main(String[] args) {
        int[] values = new int[1024];
        Arrays.setAll(values, i -> i % 17);
        long a = loop(values);
        long b = stream(values);
        if (a != b || a != 8166) throw new AssertionError(a + ":" + b);
        System.out.println("same result=" + a);
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo15.java
java Demo15
```

预期输出（普通验证模式）：

```text
same result=8166
```

## 解释结果与证据边界

两种实现都以 long 累加，避免把溢出行为不同的算法混入性能比较。JMH 工程保留相同计算，使用参数控制数组长度，输入在 Setup 中构造，两个基准均返回结果供框架消费。

默认配置包含三个 fork、三次预热、五次测量，每次迭代一秒，正式运行需要几分钟。先用很短的 smoke 参数确认工程能够启动，再按默认设置运行。smoke 成功只证明基准框架跑通，其数值不应当引用为性能结论。

附加 `-prof gc` 可以观察每操作分配等指标，但不代替生产系统的响应时间观测。微基准只回答这里的数组求和问题；它没有模拟数据库、网络和并发请求。JMH 使用方式与示例见 [OpenJDK JMH](https://github.com/openjdk/jmh)。

## 动手修改与自测

把数组长度改为 16、1024、65536，分别记录均值、误差与分配指标。然后确认同一份测试数据、JDK 与机器条件下结果是否稳定。报告所有 fork，而不是挑出最快的一次。

### src/main/java/learning/SumBenchmark.java

```java
package learning;

import java.util.Arrays;
import java.util.concurrent.TimeUnit;
import org.openjdk.jmh.annotations.*;

@State(Scope.Thread)
@BenchmarkMode(Mode.AverageTime)
@OutputTimeUnit(TimeUnit.NANOSECONDS)
@Warmup(iterations = 3, time = 1)
@Measurement(iterations = 5, time = 1)
@Fork(3)
public class SumBenchmark {
    @Param({"16", "1024", "65536"})
    public int size;
    private int[] values;

    @Setup(Level.Trial)
    public void setup() {
        values = new int[size];
        Arrays.setAll(values, i -> i % 17);
        if (loop() != stream()) throw new AssertionError("different results");
    }

    @Benchmark
    public long loop() {
        long sum = 0;
        for (int value : values) sum += value;
        return sum;
    }

    @Benchmark
    public long stream() {
        return Arrays.stream(values).asLongStream().sum();
    }
}
```

```bash
# smoke：仅验证框架运行
java -jar target/benchmarks.jar -f 1 -wi 1 -i 1 -w 100ms -r 100ms -p size=1024
# 正式测量与分配分析
java -jar target/benchmarks.jar -prof gc -rf json -rff results.json
```

输出包含 loop、stream 两组基准及参数、分数、单位；具体分数取决于实际环境，不提供虚构的预期纳秒值。
