# 04 用类加载器隔离同名类型

[English](../en/tutorial/04-class-loader-identity.md) · [中文](04-用类加载器隔离同名类型.md)

插件系统中两个类的全限定名一样，为什么仍然不能互相转换？因为类型身份不只包含名称，还包含定义它的类加载器。本篇让相同的字节码被两个加载器分别定义，直接比较 Class 对象。

## 先建立机制模型

常规 ClassLoader.loadClass 会优先复用已加载类并遵循父委派流程。父加载器能够提供的共享 API 因而可以保持一致的类型身份。父子关系表达委派关系，并不意味着父加载器的 Java 类是子加载器类的父类。

本例为了单独展示身份问题，显式调用自定义包装方法中的 defineClass，定义一个名字固定的目标。它不是完整的插件加载器，也没有实现通用的 child-first 策略。实际项目应仅对隔离的业务包应用隔离规则，让共享接口仍由共同祖先加载器定义。

类卸载也和加载器有关。长期保存插件对象、Class、线程上下文加载器或静态注册项，都可能使旧加载器无法回收；调用一次 close 并不等于 JVM 已卸载全部类。

## 完整代码

将以下内容保存为 `Demo04.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
import java.io.InputStream;
public class Demo04 {
    public static class Payload {}
    static class Isolated extends ClassLoader {
        Class<?> define(byte[] bytes) {
            return defineClass("Demo04$Payload", bytes, 0, bytes.length);
        }
    }
    public static void main(String[] args) throws Exception {
        byte[] bytes;
        try (InputStream in = Demo04.class.getResourceAsStream("/Demo04$Payload.class")) {
            if (in == null) throw new IllegalStateException("class resource missing");
            bytes = in.readAllBytes();
        }
        Class<?> a = new Isolated().define(bytes);
        Class<?> b = new Isolated().define(bytes);
        if (a == b || !a.getName().equals(b.getName())) throw new AssertionError();
        System.out.println("same name=" + a.getName().equals(b.getName()));
        System.out.println("same type=" + (a == b));
        Object value = a.getConstructor().newInstance();
        try {
            b.cast(value);
            throw new AssertionError("cross-loader cast accepted");
        } catch (ClassCastException expected) {
            System.out.println("cast rejected");
        }
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo04.java
java Demo04
```

预期输出（普通验证模式）：

```text
same name=true
same type=false
cast rejected
```

## 解释结果与证据边界

这里比较的不是两个对象是否相等，而是两个 Class 是否代表同一运行时类型。同一份字节数组没有帮它们合并身份。程序不打印加载器地址和异常完整文本，以免输出受 JVM 运行细节影响。

Payload 使用 public 的无参构造器，并且不访问外层类的私有成员。隔离加载嵌套类不代表跨加载器的 nestmate 私有访问会自然成立；实验刻意避开这个额外维度。

实际遇到“X cannot be cast to X”时，记录双方的 getClassLoader 和代码来源通常比反复检查类名更有效。类型身份定义可核对 [JVMS 5.3](https://docs.oracle.com/javase/specs/jvms/se17/html/jvms-5.html#jvms-5.3)。

## 动手修改与自测

让 a 与 b 都由同一个已缓存 Class 的变量提供，转换会成功。再尝试在同一个 Isolated 中重复 define 相同名称，观察 LinkageError，并解释为什么“相同字节”不等于允许重复定义。
