# 01 从源码追到字节码

[English](../en/tutorial/01-source-to-bytecode.md) · [中文](01-从源码追到字节码.md)

执行 `java OrderTotal` 时，操作系统最终执行的是机器指令。源码、class 文件和机器指令之间有两次容易混淆的转换：javac 将 Java 源码编译成字节码；运行时可以解释字节码，也可以由即时编译器生成本机代码。先把这条链路看清，后面的性能分析才有共同坐标。

本篇从一个订单总价函数开始。我们既运行程序，也检查编译产物；运行结果回答“算得对不对”，反汇编回答“编译器交给 JVM 的是什么”。

## 先建立机制模型

class 文件不是源码的压缩包。它包含版本号、常量池、字段、方法以及属性等结构。方法的 Code 属性可以包含字节码、异常表和调试信息。抽象方法没有普通方法那样的 Code 属性。

JVM 的栈帧模型包含局部变量表与操作数栈。局部变量保存参数和临时值，指令把值压入操作数栈，再取出值完成运算。这是解释字节码的逻辑模型，不意味着 JIT 生成的每条机器指令都必须操作一块真实的“操作数栈”。

例如整数乘法先取得两个操作数，执行 `imul`，再把乘积交给后续指令。看字节码时，应追踪值的流动，而不是把一行源码机械对应到一条指令。

## 完整代码

将以下内容保存为 `Demo01.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
public class Demo01 {
    static int total(int price, int count, int discount) {
        return price * count - discount;
    }
    public static void main(String[] args) {
        int value = total(12, 3, 5);
        if (value != 31) throw new AssertionError(value);
        System.out.println("total=" + value);
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo01.java
java Demo01
```

预期输出（普通验证模式）：

```text
total=31
```

## 解释结果与证据边界

用 `javap -c -p Demo01` 找到 total。三个 int 参数占用局部变量槽 0、1、2，因为这是静态方法，没有隐含的 this 参数。`iload_0` 和 `iload_1` 之后，操作数栈中有价格和数量；`imul` 弹出二者并压入乘积；取出折扣后执行 `isub`；最后 `ireturn` 返回整数。

`javap -v Demo01` 会列出 major version。使用本篇的 `--release 17`，应为 61。该选项同时限制源码语言、目标字节码和可使用的平台 API；单独设置目标 class 版本并不能自动阻止调用新 API。

从这个文件看不到最终 JIT 机器码。字节码里存在方法调用，也不代表热点运行时仍保留这次调用。之后的方法内联篇会继续这条证据链。

补充观察命令，在本篇 class 文件所在目录执行：

```bash
javap -c -p Demo01
javap -v Demo01
```

## 新手慢读：三张表不要混成一张

先看 [F03 的逐条操作数栈推演](../foundations/F03-亲手推演栈帧与class文件.md)，再回到本篇。局部变量表属于一次调用；class 常量池属于文件结构；运行时常量池是类相关的运行时结构。名字里有“表”或“池”，并不代表它们都是同一块内存。

| 本篇遇到的东西 | 在哪里找证据 | 它能说明什么 |
| --- | --- | --- |
| `total(12, 3, 5)` | main 的源码及调用指令 | 给 total 三个参数 |
| `(III)I` | javap 中的方法描述符 | 三个 int 参数，返回一个 int |
| `iload_0` | total 的 Code | 从本调用的槽 0 取值，不是取第 0 个堆对象 |
| `#数字` | javap 常量池与引用项 | class 内的一条编号关系，不是地址 |

从源码 total 的一行表达式到 31，可以逐项算：12×3=36，36−5=31。栈中先存输入、再存中间结果。`ireturn` 将结果交回 main 的调用位置，main 再将它赋给 value。执行 main 的过程中调用 total，不会擦掉 main 自己的调用状态。

**检查理解：**把局部变量 price 更名后，程序功能通常不变；把 price 的值改掉，结果会变。变量名主要帮助人和调试工具阅读，执行依赖的是已编译的结构与指令。你不需要先记住全部字节码助记符，只需能追踪这一次计算。

## 动手修改与自测

把参数改成 long，再观察指令是否变为 lload、lmul 和 lreturn。long 在局部变量表占两个槽，注意参数槽号的变化。然后把 total 改成实例方法，解释 this 为什么挤占槽 0。

自测：javap 能证明 CPU 实际执行了 imul 指令吗？不能；这里的 imul 是 JVM 字节码助记符，不是本机汇编的实测结果。
