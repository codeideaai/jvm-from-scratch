# 12 拆开泛型与编译器语法糖

[English](../en/tutorial/12-generics-and-sugar.md) · [中文](12-拆开泛型与编译器语法糖.md)

List<String> 在源码中限制了元素类型，为什么通过原始类型仍然能塞入整数？因为许多泛型检查发生在编译期，而 class 中仍需要擦除后的描述符与必要的类型转换。理解这一点有助于定位框架反序列化和反射注入带来的 ClassCastException。

## 先建立机制模型

泛型擦除不是“所有类型信息完全消失”。方法调用使用擦除后的类型，编译器可能插入 checkcast；Signature 属性则可以保留供工具和反射读取的泛型声明信息。运行时对象通常不会随身携带 List<String> 的实例化参数来检查每次添加。

泛型重写可能需要桥接方法。子类给出 String 返回类型，而父层擦除后的签名返回 Object，编译器生成的 bridge 负责连接两套签名。框架扫描方法时要考虑 isBridge 和 isSynthetic，避免把桥接方法当成新的业务端点。

增强 for、自动装箱以及 try-with-resources 也会被编译器转换。所谓语法糖不是“没有成本”，而是成本需要从生成后的调用与分配去理解。

## 完整代码

将以下内容保存为 `Demo12.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
import java.lang.reflect.Method;
import java.util.ArrayList;
import java.util.List;
public class Demo12 {
    interface Source<T> { T get(); }
    static class TextSource implements Source<String> {
        public String get() { return "text"; }
    }
    @SuppressWarnings({"rawtypes", "unchecked"})
    public static void main(String[] args) {
        long bridges = java.util.Arrays.stream(TextSource.class.getDeclaredMethods())
            .filter(Method::isBridge).count();
        System.out.println("bridges=" + bridges);
        List<String> values = new ArrayList<>();
        List raw = values;
        raw.add(123);
        try {
            String value = values.get(0);
            throw new AssertionError(value);
        } catch (ClassCastException expected) {
            System.out.println("heap pollution detected");
        }
        if (bridges != 1) throw new AssertionError(bridges);
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo12.java
java Demo12
```

预期输出（普通验证模式）：

```text
bridges=1
heap pollution detected
```

## 解释结果与证据边界

raw.add 接受 Object，因此写入阶段未阻止 Integer。随后 values.get 的调用结果需要转换为 String，失败发生在读取位置。这是“异常位置不等于污染位置”的典型案例；排查时应回溯未经检查的写入入口。

反汇编 TextSource，可以看到返回 String 的业务方法与返回 Object 的桥接方法。二者名字相同但描述符不同。源码层的重载规则与 class 层的方法描述方式不能直接混为一谈。

SuppressWarnings 只关闭警告，不建立运行时安全性。正常业务应尽量消除 raw type；在框架内部不可避免时，把未经检查转换限制在能验证实际对象的边界。

补充观察命令，在本篇 class 文件所在目录执行：

```bash
javap -c -v -p 'Demo12$TextSource'
javap -c -p Demo12
```

## 动手修改与自测

删除 SuppressWarnings 并使用 `javac -Xlint:unchecked Demo12.java` 查看警告。把 raw.add 的值改成字符串，说明“不再报错”为什么不能证明这种写法的类型契约完好。
