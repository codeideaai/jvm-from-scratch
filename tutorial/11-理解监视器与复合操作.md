# 11 理解监视器与复合操作

[English](../en/tutorial/11-monitors.md) · [中文](11-理解监视器与复合操作.md)

库存扣减需要同时检查余额和修改余额。只让单次读写可见不够，因为两个线程可能都读到“库存充足”。synchronized 允许把一段必须整体执行的逻辑放在同一个监视器保护下。

## 先建立机制模型

互斥只有在参与者使用同一把锁时成立。实例同步方法锁住 this，静态同步方法锁住对应 Class 对象；不同实例上的同步方法不会自动串行。锁对象最好是稳定且私有的，避免外部代码意外参与同一个锁协议。

监视器是可重入的，同一线程持有锁时再次进入同一个监视器不会把自己永久阻塞。异常退出同步块也必须释放监视器。字节码层面的同步块可以观察 monitorenter 和 monitorexit；同步方法使用方法标志表达同步属性。

锁的内部实现与优化会随 HotSpot 版本变化。不能把“偏向 → 轻量 → 重量”描述成所有版本、所有执行路径必然经过的固定流水线。先依据互斥和同步语义证明程序，再用具体版本的数据研究开销。

## 完整代码

将以下内容保存为 `Demo11.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
public class Demo11 {
    static final class Counter {
        private final Object lock = new Object();
        private int value;
        void increment() {
            synchronized (lock) { value++; }
        }
        int value() {
            synchronized (lock) { return value; }
        }
        void nested() {
            synchronized (lock) { increment(); }
        }
    }
    public static void main(String[] args) throws Exception {
        Counter counter = new Counter();
        Runnable work = () -> {
            for (int i = 0; i < 100_000; i++) counter.increment();
        };
        Thread a = new Thread(work);
        Thread b = new Thread(work);
        a.start(); b.start();
        a.join(); b.join();
        counter.nested();
        if (counter.value() != 200001) throw new AssertionError(counter.value());
        System.out.println("count=" + counter.value());
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo11.java
java Demo11
```

预期输出（普通验证模式）：

```text
count=200001
```

## 解释结果与证据边界

两个线程共享同一个 Counter 和同一个 lock，所以 value++ 的读取、相加、写回被放在一个互斥区域中。nested 在已经持锁的情况下调用 increment，验证重入路径。

锁释放还建立后续同一监视器获取的同步关系。只把写方法加锁而让读方法不遵守同一协议，不能视为对任意并发读者安全。本例读取方法也持有相同锁。

生产中多把锁的顺序需要统一，否则 A 持有库存锁等待订单锁，B 反向等待，就可能形成死锁。诊断时必须看到线程持有与等待的资源，单看线程状态 WAITING 或 BLOCKED 不够。

补充观察命令，在本篇 class 文件所在目录执行：

```bash
javap -c -p 'Demo11$Counter'
```

## 动手修改与自测

把 increment 的锁改成每次 `new Object()`，解释为什么这不再保护共享计数。再把两个线程改成操作两个 Counter，解释结果隔离与锁粒度之间的关系。使用 javap 检查异常退出同步块的释放路径。
