# 02 理解基本类型与数值边界

[English](../en/tutorial/02-primitive-types.md) · [中文](02-理解基本类型与数值边界.md)

金额、计数和标志位都是基本类型常见的使用场景。程序能够编译，不代表结果符合业务范围。本篇把整数溢出、窄化转换和浮点误差放在同一个可重复实验中，区分语言规定的结果与业务希望得到的结果。

## 先建立机制模型

int 是 32 位有符号整数。普通整数加法溢出不会自动抛异常；如果业务要求溢出必须失败，需要显式使用 Math.addExact 等检查型运算。将 int 强转为 byte 会舍弃高位，结果再按 byte 的有符号范围解释。

表达式的运算类型也很重要。两个 int 相乘时先进行 int 运算，即使随后赋值给 long，已经发生的溢出也不会被修复。需要在运算前把至少一个操作数提升为 long。

浮点数使用有限精度表示。许多十进制小数无法被二进制浮点精确表达。金额计算可以使用带明确舍入规则的 BigDecimal，且应从十进制字符串构造，而不是先把小数变成有误差的 double。

## 完整代码

将以下内容保存为 `Demo02.java`。仅依赖 JDK 17 标准库，可独立编译。

```java
import java.math.BigDecimal;
public class Demo02 {
    public static void main(String[] args) {
        System.out.println(Integer.MAX_VALUE + 1);
        System.out.println((byte) 130);
        System.out.println(50_000 * 50_000);
        System.out.println(50_000L * 50_000);
        System.out.println(0.1 + 0.2 == 0.3);
        BigDecimal sum = new BigDecimal("0.1").add(new BigDecimal("0.2"));
        if (sum.compareTo(new BigDecimal("0.3")) != 0) throw new AssertionError(sum);
        System.out.println(sum);
        try {
            Math.addExact(Integer.MAX_VALUE, 1);
            throw new AssertionError("overflow accepted");
        } catch (ArithmeticException expected) {
            System.out.println("overflow rejected");
        }
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Demo02.java
java Demo02
```

预期输出（普通验证模式）：

```text
-2147483648
-126
-1794967296
2500000000
false
0.3
overflow rejected
```

## 解释结果与证据边界

第三行发生 int 乘法溢出，第四行因左操作数带 L 而执行 long 乘法。这个差异比“最后变量是什么类型”更早发生。反汇编能分别看到 imul 和 lmul。

BigDecimal 的 compareTo 比较数值，而 equals 还考虑 scale，例如 1.0 和 1.00 的 equals 为 false。把它作为 Map 的键时，要明确业务是否区分精度表示。

boolean 的语言语义是 true/false，不能因为字节码中某些布尔操作使用整数指令，就宣称所有 boolean 字段固定占四字节。字段布局和数组布局属于实现层问题。

## 动手修改与自测

分别运行 `(long) (50_000 * 50_000)` 和 `(long) 50_000 * 50_000`，写出转换发生的位置。再让 BigDecimal 的 1 除以 3，解释为什么没有舍入策略时可能抛 ArithmeticException。
