# F02 画清内存区域与对象引用

[English](../en/foundations/F02-memory-and-references.md) · [中文](F02-画清内存区域与对象引用.md)

## 先区分盒子与通向盒子的箭头

`Box first = new Box()` 可以拆成两件事理解：产生一个 Box 对象，把指向它的引用值赋给变量 first。引用是程序用来找到对象的值，不要把它当成你能随意加减的公开内存地址。`Box alias = first` 复制引用值，没有复制 Box 的字段，也没有调用第二次构造器。

假设原对象叫 A：first → A，alias → A。改变 A.value 后，两条路径都能看到变化。若把 first 改成另一个引用，alias 仍指向 A。这里先讨论单线程语义，跨线程可见性要额外建立同步关系。

## 一张带问题的内存地图

| 区域或概念 | 用来回答什么问题 | 不要误解成 |
| --- | --- | --- |
| 每线程的 PC 与 JVM 栈 | 线程执行到哪里，当前及调用者方法处于什么状态 | 所有线程共用一个方法调用栈 |
| 栈帧 | 一次方法调用的参数、局部变量、计算中间状态是什么 | 一整个类对应一个栈帧 |
| 堆 | 实例与数组的存储和回收如何管理 | 程序进程占用的全部内存 |
| 方法区（规范概念） | 类级结构与运行时常量池等如何表示 | 任何版本都等于永久代 |
| HotSpot 元空间 | HotSpot 在本地内存中管理类元数据的一种实现安排 | 所有带 static 的值都存这里 |
| 代码缓存、本地分配、线程栈等 | 为什么堆不大但进程内存仍高 | 被 -Xmx 一并限制 |

不要急着把每个 Java 值永久放入某一个物理格子。局部变量可以持有指向堆对象的引用；被对象字段持有的引用也可以通向另一个对象。JIT 还可能把值放进寄存器，或消除某次对象分配。本图是理解执行与存活关系的模型，不是精准的机器内存测绘。

尤其注意 **JVM 运行时内存区域**和 **Java 内存模型 JMM**不同：前者讨论执行所需的数据区域，后者讨论多线程读写之间允许的行为。第 10 篇的 happens-before 属于后者。

## 完整代码

保存为 `Foundation02.java`.

```java
public class Foundation02 {
    static class Box { int value; }
    static void change(Box copy) {
        copy.value = 20;
        copy = new Box();
        copy.value = 99;
    }
    public static void main(String[] args) {
        Box first = new Box();
        first.value = 10;
        Box alias = first;
        change(first);
        if (first != alias || first.value != 20) throw new AssertionError();
        System.out.println("same object=" + (first == alias));
        System.out.println("value=" + first.value);
    }
}
```

## 编译与运行

```bash
javac --release 17 -encoding UTF-8 Foundation02.java
java -cp . Foundation02
```

预期输出：

```text
same object=true
value=20
```

## 沿着一次调用画三张图

调用 change 之前：main 的 first、alias 都通向 A，A.value=10。进入 change 时，新调用的参数 copy 收到 first 的引用值副本，也通向 A。

执行 `copy.value = 20` 时，沿箭头修改的是 A。随后 `copy = new Box()` 创建 B，并只改变 change 自己的 copy；main 中的 first、alias 没有被改写。最后的 99 写入 B，而程序输出来自 A，所以是 20。

change 返回后，该调用的局部执行状态不再需要继续保留。B 如果没有其他可达路径，可以成为回收候选；A 仍通过 main 中的活跃引用使用。这里没有调用 GC，也没有证明 B 已被回收。**调用结束**与**对象已回收**不是同一件事。

Java 参数传递始终按值进行：基本类型传值，引用类型传引用值。所谓“传对象”容易让初学者误以为方法能重新绑定调用者的变量，本例专门反驳这个误解。

**练习与答案：**把 `copy.value = 20` 删除，输出 value 会是 10；把 alias 改成 `new Box()`，same object 会是 false，原断言也会失败。思考为什么两个 Box 字段恰好相等也不代表 `==` 为 true：对象身份和内容相等是两类问题。

继续阅读主线 08 前，应能从一张容器引用图中判断“删除一个变量”和“断开所有到对象的路径”的区别。
